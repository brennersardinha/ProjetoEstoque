# Marcos de entrega

Este plano complementa o roadmap e serve para acompanhamento. Cada marco exige revisão do incremento e aceite dos critérios relacionados; estimativas iniciais são indicativas.

| Marco | Resultado demonstrável | Critério de saída |
|---|---|---|
| M0 — Especificação validada | Decisões críticas e amostra da planilha revisadas com responsável da loja | P-01 a P-10 resolvidas ou com aceite explícito de risco/adiamento |
| M1 — Base técnica | API inicia, banco migra, painel/app executam em desenvolvimento | Setup repetível e migração limpa aprovada |
| M2 — Catálogo | Login, categoria, produto, identificador e importação | Testes de autorização/importação e zero à esquerda aprovados |
| M3 — Inventário operacional | Abrir balanço, ver pendências, ler código e registrar contagem | Integridade/idempotência/concorrência aprovadas |
| M4 — Revisão e relatórios | Recontagem, aprovação, encerramento, dashboard, XLSX/PDF | Resultados conferidos com exemplos da loja |
| M5 — Pronto para piloto | Segurança local, backup/restauração, treinamento e aparelhos reais | Checklist de piloto assinado |
| M6 — Piloto concluído | Balanço em uma categoria, feedback e correções | Defeitos críticos fechados e decisão sobre expansão |

## Revisão de marco

Para cada marco, registrar data, versão, itens concluídos, testes executados, defeitos/pedências, decisão de aceite e responsável. Não usar percentuais de progresso como substituto para evidência funcional.
